# 案件问答与笔记沉淀

## 写入时点

明确属于已登记案件且本轮产生可复用信息时，在向用户发送最终回答前运行 `scripts/case_note.py append`。这是共同工作区内的正常办案留痕；案件不明确时不得猜测路径或写入。

应写入：

- 用户新增、纠正或确认案件事实；
- 用户确定、改变或否定办案口径；
- 形成可复用的法律结论、诉讼策略或风险判断；
- 发现重要矛盾、证据缺口或待办；
- 新增或修改文稿、复核和定稿成果。

不写入：一般法律知识、与具体案件无关的解释、重复既有结论、临时措辞讨论、没有产生新信息的追问、模型未经材料支持的猜测。

## 条目格式

脚本按以下紧凑格式追加：

```text
[日期 时间 · 类型 · harness]
- 问题：本轮实际问题。
- 结论：一至三句话的可复用结论。
- 前提：已核事实、用户陈述或既有口径。
- 风险/待核：事实、法律时点或材料缺口。
- 后续：补检、补证、改稿或待用户决定事项。
- 关联成果：案件目录内的相对路径。
```

只填写有内容的字段。不得复制整份回答、检索报告或专项分析；详细内容留在成果文件，案件笔记保留摘要与路径。脚本使用同日“类型＋问题＋结论＋成果路径”哈希去重。

## 事实边界

- 用户陈述但未回源的事实使用 `fact_lead`，脚本显示为“线索（未核）”。
- 问答笔记不是结构化事实入账。需要写入 `_case_state.json.facts` 时，另行核对原件并使用共同状态工具。
- 检索结果、法律分析和模型推断不得改写成案件事实。

## 系列案件

- 只影响单一子案：完整条目写子案笔记。
- 影响多个子案或系列统一口径：写系列总笔记。
- 同时影响两级：完整条目写子案，并通过 `--series-root` 与 `--series-summary` 在总笔记追加一句摘要及子案笔记路径。
- 子案没有独立 `_case_state.json` 时仍可写子案笔记；结构化状态继续由已登记的系列根管理，除非另行决定为子案建状态。

## 类型

`qa`、`user_instruction`、`strategy`、`fact_lead`、`todo`、`document`、`review`、`final`。选择最能说明本轮新增价值的一种，不为同一内容重复写多类。
